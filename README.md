# Task Board — independent AppBoundry application

Task Board is a small full-stack CRUD application. The browser UI is served by
`src/server.mjs`; task records are persisted through the local FeltDB provider
(`@feltdb/core`) and are never silently replaced with an in-memory store.

## Development

```sh
npm install
npm test
npm run dev
```

Open <http://127.0.0.1:4173>. Set `FELTDB_PATH` to choose the durable state
directory. Provider failures are reported as errors rather than being hidden.

## Build, verify, and certify

The repository uses the published AppPort commands. The checked-in WASM
implementation is the input to every artifact build:

```sh
npm run app:build
npm run app:package
npm run app:verify
npm run app:certify
npm run app:hash
```

`app:certify` invokes the published customer-artifact verification command.
The AppBoundry package reserves `product certify` for the AppBoundry platform
artifact; customer applications are certified by the documented `verify`
workflow.

The generated `artifacts/task-board.app` directory contains the immutable
`manifest` and `application.wasm`. It is committed, while the browser upload
(`.appbundle`) is ignored because it is derived from the same immutable files.
Deploy the exact committed `.app` after verification; do not rebuild between
verification and deployment.

## GitHub source metadata

`src/github-source.ts` is the typed discovery contract. The UI displays
repository and default branch only when the connected provider supplies them.
Branch, commit, and Projects metadata are explicitly shown as unavailable when
the provider does not expose them; this application never fabricates GitHub
values. Set `GITHUB_*` variables only from connection/discovery data.

## Artifact boundary and runtime

The repository is development source. AppBoundry runs the committed `.app`
artifact and uses its provider contracts; it does not need `src/`, `.git/`,
`node_modules/`, or a development server to inspect or deploy the artifact.
The browser server is the development/full-stack host used to exercise the
same application contract. Application identity is
`com.rkendel1.taskboard`, version `1.0.0`; a later revision changes the version
without changing the identity.

## CI

CI installs dependencies, runs tests, builds the AppPort package, verifies it,
and compares the generated artifact identity with the committed artifact. A
future reproducible-build check should fail rather than silently replacing the
committed artifact if generated bytes differ.
